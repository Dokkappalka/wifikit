# Ручной тест-план (сценарий приёмки)

> Полный список отдельных тест-кейсов с номерами — `docs/TESTCASES.md`. Здесь — сквозной сценарий
> от установки до отчёта, чтобы пройти всё за один заход.

Порядок важен: каждый блок опирается на предыдущий. «Ожидание» — это то, что должно быть
на экране; если расходится, останавливайтесь и пишите мне номер шага.

Всё делаем на **своей** точке (свой роутер или телефон в режиме точки доступа), которую
разрешено ломать. Телефон удобнее: его легко вернуть к жизни.

## 0. Подготовка UTM (один раз)

1. VM: **QEMU**, не Apple Virtualization. Настройки → USB → включить «USB-устройства → делиться с хостом».
2. Контроллер USB — **xHCI 3.0**.
3. Оба адаптера — в активный USB-хаб (с питанием), потом пробросить в VM через меню 🔌.
4. В гостевой Ubuntu: `lsusb` — оба адаптера видны. `iw dev` — два интерфейса `wlx…`.
5. `sudo apt update && sudo apt install -y git` (если ещё нет).

Ожидание: в `iw dev` ровно два wireless-интерфейса, оба не заблокированы: `rfkill list` → `Soft blocked: no`.

## 1. Установка

```bash
sudo packaging/install.sh
```

Проверить по шагам вывода:
0. «0/5 окружение: Ubuntu …» — убедитесь, что дистрибутив тот, что вы ждали (22.04 и 24.04 поддерживаются оба).
1. «1/5 системные пакеты» — без красных `E:`; допустимо предупреждение про Qt-библиотеки.
   Если появилось `apt не может разобрать индексы репозиториев` или `Splitting up … into data and signature failed` —
   это поломка apt в самой гостевой системе, не установщика. Выполните блок команд, который печатает скрипт
   (место на /var, `rm -rf /var/lib/apt/lists/*`, `dpkg --configure -a`, `apt-get -f install`, `apt-get update`),
   и запустите установщик снова. Обход без apt: `sudo WIFIKIT_SKIP_APT=1 packaging/install.sh` (файлы встанут,
   зависимости — нет, дальше нужен мастер диагностики).
2. «2/5 PySide6» — либо «найден в системном Python», либо «делаю изолированное окружение …/venv». Строка `Unable to locate package python3-pyside6` больше не должна появляться как ошибка.
3. «3/5 hcxdumptool» — версия **7.x**. На Ubuntu 24.04 скрипт собирает её сам; в конце «собрано: hcxdumptool 7.x».
4. «5/5 проверка» — «модули wifikit на месте», список не найденных бинарей пуст.
5. В конце — «готово. Запуск: wifikit».

Если в конце «установка завершена с замечаниями» — запишите список, он и есть вход в диагностику.

## 2. Запуск и права

1. `wifikit` из терминала (или из меню).
2. Появится запрос polkit на пароль — введите. Окно приложения при этом **не должно** закрыться.
3. В журнале внизу: `wifikit 0.1.0 · подключаюсь к демону…`, затем `демон подключён`.

Ожидание: окно открывается, шапка пустая («проект не открыт»), в «Сенсор»/«Фейк-точка» уже подставлены адаптеры.
Если окно не появилось и в терминале `qt.qpa.plugin: could not load the Qt platform plugin "xcb"` — не хватает libxcb-*, повторите `sudo packaging/install.sh`.

Проверка, что демон жив и непривилегированный GUI его не подменяет:

```bash
ls -l $XDG_RUNTIME_DIR/wifikit.sock      # должно быть srw------- и ваш пользователь
pgrep -af wifikit                        # один процесс демона под root
```

## 3. Диагностика (страница «Диагностика»)

1. Список зависимостей: все строки `ok`, «не хватает: …» отсутствует. `hcxdumptool 7.x`, `hashcat 6.x+`.
2. Блок адаптеров: у каждого интерфейса драйвер (`mt7921u`, `88XXau`, `ath9k_htc` и т.п.) и роли **сенсор / AP**.
3. Кнопка «Снять rfkill-блок» → в журнале `unblock` без ошибок.
4. Кнопка «Устройства hashcat» → появляется строка с типом устройства. `Type.: GPU` — хорошо; `CPU` — крошить будет медленно, это ожидаемо в виртуалке.

Провал: если у обоих адаптеров нет роли «сенсор» — драйвер не умеет monitor. Это стоп: с таким железом дальше идти нельзя.

## 4. Проект

1. Слева внизу «Новый проект» → имя `тест-1` → OK.
2. В шапке появилось имя проекта, в журнале путь `~/wifikit-projects/…`.
3. Закройте приложение, откройте снова, «Открыть» → выберите ту же папку → имя проекта вернулось.

## 5. Скан

1. Страница «Точки», «Сканировать», 15 с.
2. Таблица заполняется: SSID, BSSID, канал, сигнал, защита, «чем брать».
3. Найдите свою тестовую сеть: в колонке «Защита» — `WPA2`, в «Чем брать» — `WPA2: PMKID → деаут + захват`.
4. Клик по строке → в шапке справа появился BSSID, на страницах «Захват» и «Злой двойник» подставилась цель.

Дополнительно проверить на соседях: у WPA3-сети бейдж `WPA3`, у точки с PMF — `PMF!` и подсказка «PMF обязателен».

## 6. Захват PMKID (быстрый путь)

1. «Захват» → «Сначала PMKID», лимит 2 мин.
2. В журнале команда `hcxdumptool -i wlx… -c <кан>a … --exitoneapol=1`.
3. Через 10–60 с захват останавливается сам.

Ожидание при успехе: «хэш получен: PMKID 1, EAPOL 0».
Если «хэш не получен» — это нормальный исход для роутеров, которые не отдают PMKID; переходите к п.7.

## 7. Захват рукопожатия с деаутом

1. На телефоне подключитесь к тестовой сети (чтобы был клиент).
2. «Захват» → «Захватить», лимит 5 мин, галочка «Деаут при захвате» включена.
3. Ожидание: телефон на 1–2 секунды выпадает из сети и переподключается; в журнале растут строки `aireplay-ng`, затем `hcxdumptool` выходит сам.
4. Результат: «хэш получен: PMKID 0, EAPOL 1» и в примечаниях «replaycount проверен», если пара чистая.

Провал и что значит:
- `PMF обязателен` в момент старта деаута — приложение откажется: так и должно быть, берите PMKID.
- «есть EAPOL без M2M3» — деаут не дошёл до клиента. Проверьте, что клиент реально в сети и что деаут-адаптер на нужном канале.

## 8. Крошилка: словарь с правилами

1. Захватите хэш (п.6 или 7). Страница «Крошилка», внизу должна быть строка «нет хэша» **исчезнуть** — вместо неё появится найденный хэш.
2. «Вендорские кандидаты» → в поле «Словарь» подставился путь `…/candidates.txt`.
3. Атака «словарь», правила `best64`, «Запустить».
4. Ожидание: прогресс ползёт, «Скорость» показывает H/s, при совпадении в «Найдено» появляется пароль.

## 9. Крошилка: перебор по позициям (новое)

Тестовый пароль задайте сами на роутере, например `Qwerty-123`.

1. Атака → «по позициям». Появляется таблица позиций и «длина от … до …».
2. Настройте:
   - позиция 1: тип `ПРОПИСНЫЕ`;
   - позиции 2–5: `строчные`;
   - позиция 6: `символ` → `-`;
   - позиции 7–9: `цифры`;
   - длина от 9 до 9.
3. Под таблицей должно появиться: `маска ?u?l?l?l?l-?d?d?d · перебор …` (для `?u?l…` — 26·26^4·10^3 ≈ 11.8 млрд; в подсказке это «11.8 млрд»).
4. «Запустить». В журнале — команда hashcat с `-a 3` и этой маской.

Ожидание: пароль `Qwerty-123` находится, строка появляется в «Найдено».

Проверка диапазона длин:
5. «длина от 9 до 11» → в подсказке маска добита типом последней позиции (`?d?d?d`) и добавлено `--increment-min=9 --increment-max=11`. Перебор стартует с 9 символов.

Проверка своего набора:
6. Позиция 1: тип `свой набор`, значение `QWE`. Подсказка показывает `?1` и `-1 QWE` в команде.
7. Заведомо неверная конфигурация: позиция «символ» со значением из двух букв → ошибка «нужен ровно один символ» (диалог, приложение не падает).
8. Пять разных «своих наборов» → ошибка «больше 4 разных наборов hashcat не примет».

## 10. Злой двойник

1. Оба адаптера назначены в шапке: «Сенсор» — один, «Фейк-точка» — другой. Попробуйте выбрать один и тот же → приложение откажется.
2. Страница «Злой двойник»: шаблон `Роутер TP-Link`, «Клонировать BSSID» включено, «Проверять пароль по хэшу» включено.
3. «Поднять точку». Ожидание: `поднята · SSID <ваша сеть> · клиентов 0`.
4. На телефоне: в списке сетей появилась точка с тем же именем, что и настоящая (может быть две одинаковые). Подключитесь к **новой** (та, что без интернета).
5. Должно само открыться окно с формой (captive portal). Если не открылось — откройте браузер и зайдите на любой http-сайт.
6. Введите заведомо неверный пароль → форма сообщает «неверный пароль» и остаётся.
7. В приложении на странице «Злой двойник» в таблице «Вводы в портале» появляются строки: время, `password=…`, вердикт.
8. Введите правильный пароль → «подключено». В таблице вердикт «верно», а в шапке проекта — найденный пароль.

Ожидание: пароль подтверждается **по захваченному хэшу**, а не по факту нажатия; проверить это можно, введя пароль от другой сети — он должен получить «неверный».

9. «Погасить». Ожидание: точка исчезает из эфира, телефон возвращается к настоящей сети.
10. Свой шаблон: «Загрузить свой HTML/ZIP» → выберите свой html с `<input type="password">`. Шаблон появляется в списке. Файл без поля пароля → ошибка «в форме нет поля type=password».

## 11. Отчёт и проект

1. Слева «Отчёт» → в журнале путь `…/report/report-*.md`.
2. Откройте файл: SSID, BSSID, канал, шифрование, PMF, адаптеры, найденный пароль, заметки, список файлов.

## 12. Уборка после сбоя (обязательный тест)

1. Поднимите фейк-точку (п.10), затем в терминале: `sudo kill -9 $(pgrep -f wifikit/daemon.py)`.
2. Ожидание: приложение пишет «демон не отвечает».
3. Запустите `wifikit` снова, введите пароль polkit.
4. В журнале появится «уборка: снята таблица nft wifikit; остановлен hostapd…».
5. Проверьте руками:

```bash
sudo nft list tables | grep wifikit   # пусто
pgrep -a hostapd; pgrep -a dnsmasq    # пусто
iw dev                                 # сенсор снова в managed, не monitor
```

Ожидание: после аварии не осталось ни висящей точки, ни правил перенаправления, ни адаптера в monitor.

## 13. Пограничные случаи

1. **Язык**: кнопка «en» в шапке меняет часть надписей; после перезапуска интерфейс английский. Обратно — «ru».
2. **Один адаптер**: отключите второй → «Злой двойник» не даст поднять точку («нужны два разных адаптера»), «Захват» продолжает работать.
3. **WPA3-only** сеть: скан покажет `WPA3`, в подсказке «крошить нечем»; крошилка на её хэше не запустится.
4. **Открытая сеть**: в «Чем брать» — «открытая сеть — портал сразу»; деаут не нужен.
5. **Пустой словарь**: укажите пустой файл → крошилка сразу завершится с прогрессом 100 % и без находок (не должна зависнуть).

## 14. Что считать успехом приёмки

- Все пункты 2–12 без падений приложения и без «висящих» ресурсов после п.12.
- Захват: получен хотя бы один валидный хэш (PMKID или EAPOL).
- Крошилка: пароль найден и по словарю, и перебором по позициям.
- Портал: неверный пароль отвергнут, верный подтверждён по хэшу.
- Отчёт открывается и содержит пароль и факты по точке.

Если что-то падает — мне нужен номер шага, текст из «Журнала» и вывод `pgrep -af "wifikit|hostapd|dnsmasq"`. Этого достаточно, чтобы чинить без догадок.
