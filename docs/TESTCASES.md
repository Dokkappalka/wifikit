# Тест-кейсы wifikit

Полный список для ручного прогона. Идите сверху вниз: блоки зависят от предыдущих.
Формат: **шаги → ожидание**. Если ожидание не совпало — это баг, фиксируйте номер (например `M7`),
текст из «Журнала» и хвост `~/.local/state/wifikit/daemon.log`.

Обозначения: `!` — критично для работы, `~` — косметика/удобство, `(`P`)` — негативный сценарий.

Что понадобится: своя точка (роутер или телефон-хотспот), два USB-адаптера, клиент (телефон/ноут)
для подключения к точке. Пароль точки знаете вы — это и есть эталон для проверок.

---

## A. Установка и запуск

**A1 · Установка на чистую систему**
`sudo packaging/install.sh`
→ «0/5 окружение: Ubuntu …», шаги 1–5 без красных `E:`; в конце «готово. Запуск: wifikit».

**A2 · hcxdumptool 7**
Вывод шага 3/5 и затем `hcxdumptool -v` → версия **7.x**. Если в системе было 6.x, установщик пишет «собрано: …».

**A3 · PySide6**
`/usr/lib/wifikit/venv/bin/python -c "import PySide6; print(PySide6.__version__)"` → версия печатается.
Либо системный `python3 -c "import PySide6"` работает.

**A4 · Qt-библиотеки**
`wifikit` из терминала → окно открылось, в консоли нет `could not load the Qt platform plugin "xcb"`.

**A5 · Запрос прав**
Запуск `wifikit` → впервые спрашивает пароль polkit; после ввода окно живо, демон работает.

**A6 · Повторный запуск без пароля**
Закрыть окно, запустить снова → пароль может спроситься снова (норма), окно открывается.

**A7 · Демон не остаётся после закрытия**
Закрыть окно → `pgrep -af wifikit/daemon.py` пусто; `ls $XDG_RUNTIME_DIR/wifikit.sock` — файла нет.

**A8 (P) · Отмена пароля polkit**
Отменить ввод пароля → приложение показывает ошибку с текстом лога, не висит и не падает;
через ~20 с само пробует подключиться снова (в журнале «повторная попытка»).

**A9 (P) · Без прав**
Запуск GUI от root (`sudo wifikit`) → либо работает, либо внятная ошибка; не должно быть «тихого» отказа.

**A10 · Лаунчер из меню**
`wifikit` находится в меню приложений и запускает то же самое.

**A11 (P) · Нет второй сети/интернета**
Отключить интернет у VM → установка падает с понятным «нет сети», а не с мусором в консоли.

**A12 ~ · Иконки и заголовок**
В заголовке окна «wifikit», в сайдбаре название и версия.

## B. Связь с демоном

**B1 · Сокет принадлежит вам**
`ls -l $XDG_RUNTIME_DIR/wifikit.sock` → `srw------- вы:ваша_группа`.

**B2 · Один демон**
`pgrep -af wifikit/daemon.py` → ровно один процесс; повторный запуск второго GUI не плодит демонов.

**B3 · Лог демона**
Файл `~/.local/state/wifikit/daemon.log` существует и содержит строку `wifikit daemon up`.

**B4 ! · Все действия проходят**
Любое действие (скан, диагностика, создание проекта) выполняется, без «нет связи с демоном».

**B5 (P) · Демон убит**
`sudo kill -9 $(pgrep -f wifikit/daemon.py)` → первое же действие даёт «связь с демоном потеряна»
с путём к логу; следующее действие после перезапуска окна работает.

**B6 (P) · Битый сокет**
Оставить файл сокета без слушателя (`kill -9` демона) → GUI сам удаляет остаток и поднимает демон заново.

**B7 ~ · Журнал в окне**
Каждое действие видно в нижней панели «Журнал» (команда или результат).

**B8 (P) · Мусор в RPC**
`echo 'not json' | socat - UNIX-CONNECT:$XDG_RUNTIME_DIR/wifikit.sock` → ответ с ошибкой `bad_json`, демон жив.

## C. Диагностика

**C1 ! · Зависимости**
Страница «Диагностика» → все строки `ok`, «не хватает: …» отсутствует.

**C2 ! · Версии**
В списке: hcxdumptool 7.x, hashcat ≥ 6.0, hcxptools ≥ 6.2, hostapd, dnsmasq, nft, iw, nmcli.

**C3 · Адаптеры и роли**
У обоих адаптеров видны драйвер и роли («сенсор», «AP»).

**C4 · Устройства hashcat**
«Устройства hashcat» → печатается `Backend Device ID … Type.: CPU|GPU`.

**C5 · rfkill**
«Снять rfkill-блок» → в журнале `ok`, в `rfkill list` всё разблокировано.

**C6 (P) · Нет инструмента**
`sudo mv /usr/bin/hashcat /usr/bin/hashcat.bak` → диагностика показывает его отсутствие; вернуть назад.

## D. Адаптеры

**D1 ! · Назначение ролей**
В шапке выбрать Сенсор = `wlx…`, Фейк-точка = другой `wlx…` → оба применились, выбор запомнился.

**D2 (P) · Один и тот же адаптер**
Выбрать один и тот же интерфейс на обе роли → приложение отказывает с понятным текстом.

**D3 (P) · Непригодный адаптер**
Пункт с пометкой «(непригоден)» недоступен для выбора.

**D4 · Обновление списка**
Выдернуть и вставить адаптер → «Обновить» показывает актуальный список.

**D5 ~ · Имя интерфейса**
Имя вида `wlx…` стабильно между запусками (не меняется на `wlan0`).

**D6 (P) · Нет адаптеров вообще**
Оба отключены → «Обновить» пишет в журнал «адаптеров не найдено», приложение не падает.

## E. Проект

**E1 ! · Создание**
«Новый проект» → имя в шапке, в журнале путь `~/wifikit-projects/…`; папка существует.

**E2 · Состав папки**
Внутри `project.json`, подпапки `dump/ hash/ ap/ report/`.

**E3 · Права**
`stat -c %a project.json` → `600`.

**E4 · Открытие после перезапуска**
Закрыть окно, открыть снова, «Открыть» → выбрать папку → имя проекта и цель вернулись.

**E5 (P) · Не проект**
«Открыть» и выбрать пустую папку → ошибка «в … нет проекта», без падения.

**E6 · Цель записывается**
После выбора точки в «Точках» открыть `project.json` → `target` заполнен BSSID/SSID/каналом.

**E7 ~ · Заметки**
Заметки из действий (захват, портал) появляются в `project.json` и в отчёте.

## F. Скан

**F1 ! · Список сетей**
«Точки» → «Сканировать» → таблица заполняется в течение 15 с, видна ваша точка.

**F2 · Поля строки**
SSID, BSSID (в нижнем регистре), канал, RSSI, защита, подсказка — все заполнены.

**F3 ! · Бейджи защиты**
У WPA2-точки `WPA2`; у WPA3 — `WPA3`; у точки с обязательным PMF — `PMF!` и подсказка про деаут.

**F4 ~ · Скрытая сеть**
Точка без SSID показывается как `<скрытая>`, а не пустой строкой.

**F5 · Сортировка по сигналу**
Ближние сети выше дальних.

**F6 · Выбор цели**
Клик по строке → в шапке справа BSSID, на «Захвате» и «Злом двойнике» подставилась цель.

**F7 (P) · Скан без сенсора**
Снять роль Сенсор → «Сканировать» → ошибка «не назначен адаптер-сенсор».

**F8 (P) · Повторный скан**
Запустить скан дважды подряд → второй не ломает состояние, список обновляется.

## G. Захват PMKID

**G1 · Запуск**
«Захват» → «Сначала PMKID», лимит 2 мин → в журнале команда `hcxdumptool … --exitoneapol=1`.

**G2 ! · Авто-стоп**
При удаче захват останавливается сам, без нажатия кнопки.

**G3 ! · Результат при успехе**
«хэш получен: PMKID N», в `hash/` появился `.hc22000`, в нём строки `WPA*01`.

**G4 (P) · Точка без PMKID**
«хэш не получен» с примечанием — это норма, не баг.

**G5 · Остановка вручную**
«Остановить захват» → процесс завершается, адаптер возвращается в managed (`iw dev` → type managed).

## H. Захват рукопожатия и деаут

**H1 · Включение деаута**
Галочка «Деаут при захвате» → в журнале видны строки `aireplay-ng --deauth`.

**H2 ! · Клиент выпадает**
Телефон, подключённый к точке, на 1–2 с теряет сеть и переподключается.

**H3 ! · Хэш получен**
«хэш получен: EAPOL 1» и в примечаниях проверка replaycount, если пара чистая.

**H4 (P) · Без клиента**
Никто не подключён → «хэш не получен» (PMKID 0, EAPOL 0), без зависания.

**H5 (P) · PMF-точка**
Точка с обязательным PMF → деаут не стартует, ошибка «PMF обязателен», захват можно вести пассивно.

**H6 · Таймаут**
Лимит 1 мин → захват останавливается по таймауту.

**H7 ~ · Канал**
В команде `hcxdumptool` канал совпадает с каналом цели.

## I. Крошилка: общее

**I1 (P) · Без хэша**
Проект без захвата → «Запустить» → ошибка «нет захваченного хэша».

**I2 ! · Хэш виден**
После захвата вверху «Крошилки» больше нет «нет хэша», а «Запустить» работает.

**I3 · Прогресс и скорость**
Во время работы заполняется прогресс-бар, «Скорость» показывает H/s (не пусто).

**I4 · Остановка**
«Стоп» → процесс hashcat завершён, кнопки вернулись в исходное состояние.

**I5 · Продолжение**
Запустить снова → уже проверенные кандидаты не пересчитываются (потифайл в проекте).

**I6 ~ · Найденное**
При совпадении в блоке «Найдено» появляется пароль.

## J. Словарь и правила

**J1 ! · Словарь**
Выбрать файл словаря с паролем вашей точки внутри → пароль найден.

**J2 · Выбор файла**
Кнопка «…» открывает диалог, путь подставляется в поле.

**J3 (P) · Пустой словарь**
Файл из 0 строк → hashcat завершается без находок, приложение не виснет.

**J4 (P) · Нет файла**
Указать несуществующий путь → ошибка «словарь не найден».

**J5 · Правила best64**
Словарь, где пароль без модификаций (например `qwerty-123` в словаре как `Qwerty`), + best64 → найден,
если правило покрывает модификацию.

**J6 · Вендорские кандидаты**
«Вендорские кандидаты» → появляется `hash/candidates.txt`, он подставлен в поле словаря, запуск работает.

**J7 ~ · Правило не найдено**
Выбрать правило, которого нет в `/usr/share/hashcat/rules` → ошибка «правила не найдены».

## K. Маска

**K1 ! · Простая маска**
Маска `?d?d?d?d?d?d?d?d` на точке с 8-значным паролем → найдено (или быстро исчерпано, если пароль другой).

**K2 · Свой ввод**
Вписать маску вручную в редактируемое поле → она уходит в аргументы (`-a 3`).

**K3 (P) · Пустая маска**
Очистить поле → ошибка «маска пуста».

**K4 (P) · Мусор в маске**
Маска `??` или `?x` → hashcat ругается, приложение показывает ошибку, не падает.

**K5 ~ · Длина по маске**
Число символов в маске равно длине пароля, который реально ищется.

---

## L. Словарь + маска (гибрид)

**L1 ! · Суффикс**
Словарь со словом-основой + маска `?d?d` → находятся пароли вида «слово12».

**L2 · Пустой словарь**
Гибрид без словаря → ошибка «словарь не найден».

**L3 (P) · Маска не из цифр**
Маска `?a?a` на большом словаре → приложение предупреждает объёмом не сразу, но не падает.

**L4 ~ · Аргументы**
В журнале видно `-a 6`.

## M. По позициям

**M1 ! · Таблица появилась**
Атака «по позициям» → видна таблица «позиция / тип / значение» и поля «длина от … до …».

**M2 ! · Чтение строк**
Тип и значение в ячейках читаются полностью, текст не обрезан по вертикали, поле ввода не «худее» строки.

**M3 · Счётчик позиций**
«+ позиция» добавляет строку, «− позиция» удаляет последнюю; нумерация пересчитывается.

**M4 ! · Предпросмотр маски**
8 позиций «любой», длина 8–8 → под таблицей `маска ?a?a?a?a?a?a?a?a · перебор …
(≈ 6.6 квадрлн)`. Обновилось без нажатия кнопок.

**M5 ! · Типы символов**
Поставить `ПРОПИСНЫЕ`, `строчные`, `цифры` → в маске `?u`, `?l`, `?d` соответственно.

**M6 ! · Фиксированный символ**
Тип «символ» значение `-` → в маске дефис на этой позиции, а `-1`/`-2` в аргументах не появляются.

**M7 ! · Свой набор**
Тип «свой набор» значение `QWE` → в маске `?1`, в аргументах `-1 QWE`.

**M8 (P) · Два символа в «символ»**
Значение `ab` → ошибка «нужен ровно один символ», приложение не падает.

**M9 (P) · Наборов больше четырёх**
Пять разных своих наборов → ошибка «больше 4 разных наборов hashcat не примет».

**M10 ! · Диапазон длин**
4 позиции «цифры», длина от 4 до 6 → маска `?d?d?d?d?d?d`, в журнале `--increment-min=4 --increment-max=6`.

**M11 (P) · Длина меньше позиций**
6 позиций, длина от 4 → предупреждение «поднял до 6» в подсказке, перебор считается от 6.

**M12 (P) · Длина больше 63**
Выставить 63+ → ошибка, запуск не начинается.

**M13 ! · Перебор находит пароль**
Своя точка с паролем вида `Qwerty-123`: позиции `ПРОПИСНЫЕ`, `строчные`×4, `символ -`, `цифры`×3,
длина 9 → пароль найден, появляется в «Найдено».

**M14 ~ · Значение в проекте**
После запуска в `project.json` есть заметка с маской и объёмом перебора.

## N. Злой двойник: точка

**N1 (P) · Один адаптер**
Снять вторую роль → «Поднять точку» недоступно с текстом «нужны два разных адаптера».

**N2 ! · Подъём**
«Поднять точку» → «поднята · SSID … · клиентов 0»; в `ap/` появились `hostapd.conf`, `dnsmasq.conf`, `portal.nft`.

**N3 ! · Точка видна телефону**
Телефон видит сеть с именем цели (возможно две одинаковые).

**N4 ! · Клиент подключается**
Подключение к фейковой сети проходит без пароля, телефон получает адрес `192.168.77.x`.

**N5 · Список клиентов**
В таблице «Клиенты» появляется MAC и IP телефона.

**N6 (P) · Клон BSSID выключен**
Снять «Клонировать BSSID» → точка поднимается со своим MAC, но с тем же SSID.

**N7 ! · Погасить**
«Погасить» → точка исчезает из эфира, телефон возвращается к настоящей сети.

**N8 ! · Уборка после гашения**
`sudo nft list tables | grep wifikit` пусто; `pgrep -a hostapd` пусто; `pgrep -a dnsmasq` пусто.

**N9 (P) · Занятый канал**
Поднять точку на 5 ГГц-канале, который адаптер не умеет → внятная ошибка hostapd, а не тишина.

**N10 (P) · Двойной подъём**
«Поднять точку» дважды → «фейк-точка уже поднята», второй hostapd не запускается.

## O. Портал

**O1 ! · Шаблоны в списке**
В выпадающем списке 6 шаблонов (TP-Link, Keenetic, кафе, отель, прошивка, двухшаговый).

**O2 ! · Автооткрытие формы**
После подключения к фейковой сети браузер сам открывает форму (captive portal).

**O3 (P) · Заход на любой сайт**
Ввести `http://example.com` → редирект на форму.

**O4 ! · Неверный пароль**
Ввести заведомо неверный → «неверный пароль», форма остаётся.

**O5 ! · Верный пароль**
Ввести верный → «подключено»; в таблице «Вводы в портале» вердикт «верно»; пароль появился в проекте.

**O6 ! · Все поля сохраняются**
В шаблоне с полями «имя/телефон/пароль» заполнить все → в таблице видны все три, не только пароль.

**O7 · Свой шаблон**
Загрузить свой html с `input type=password` → шаблон в списке, портал отдаёт именно его.

**O8 (P) · Свой шаблон без пароля**
Файл без поля пароля → ошибка «в форме нет поля type=password», шаблон не появляется.

**O9 (P) · Проверка недоступна**
Убрать хэш (или `hcxpmktool`) → портал отвечает «проверяем…» и не объявляет пароль неверным.

**O10 ~ · Просмотр портала на ПК**
Кнопка «Открыть портал» открывает `http://192.168.77.1:8080/` (работает при подключении к фейк-точке
с этой же машины или из браузера телефона).

## Q. Аварии и уборка

**Q1 ! · kill -9 демона на поднятой точке**
Поднять точку → `sudo kill -9 $(pgrep -f wifikit/daemon.py)` → перезапустить приложение →
в журнале «уборка: снята таблица nft wifikit; остановлен hostapd…».

**Q2 ! · После уборки ничего не висит**
`nft list tables | grep wifikit`, `pgrep -a hostapd`, `pgrep -a dnsmasq` → пусто;
`iw dev` → сенсор в managed.

**Q3 ! · kill -9 во время захвата**
Захват идёт → убить демон → перезапуск → `pgrep -a hcxdumptool` пусто, адаптер в managed.

**Q4 · Зависший hashcat**
Убить демон во время крошилки → перезапуск → `pgrep -a hashcat` пусто.

**Q5 (P) · Закрытие окна во время работы**
Закрыть окно при поднятой точке → всё погашено (проверить как в Q2).

**Q6 ~ · Незакрытый откат**
Файл `~/.local/state/wifikit/pending_rollback.json` после чистого выхода содержит `"reason": "clean"`.

## Как сообщать о баге

1. Номер кейса (`M7`), что делали, что ждали, что получили.
2. Текст из нижней панели «Журнал» (последние 20 строк).
3. `~/.local/state/wifikit/daemon.log` (последние 40 строк).
4. Если дело в железе — `iw dev`, `iw phy | head -40`, `hcxdumptool -I <iface>`.

Этого достаточно, чтобы воспроизвести и починить без переписки.
