# wifikit — как это работает

Документ отвечает на вопросы «что делает эта кнопка» и «почему получилось так». Ручной план проверки —
`docs/TESTCASES.md`. Ограничения платформы — `docs/PLATFORMS.md`. Архитектура — `docs/ARCHITECTURE.md`.

---

## 1. Из чего состоит приложение

Два процесса:

- **GUI** (`wifikit`) — работает от вашего пользователя, без root. Ничего привилегированного не делает.
- **демон** (`/usr/lib/wifikit/daemon.py`) — запускается через `pkexec` (спросит пароль один раз),
  работает от root и выполняет всё, что требует прав: перевод адаптера в monitor, инъекцию,
  запуск `hostapd`/`dnsmasq`, правила `nftables`, `hashcat`.

Общаются они через unix-сокет `$XDG_RUNTIME_DIR/wifikit.sock` (обычно `/run/user/1000/wifikit.sock`),
владелец — вы, права `0600`. Формат — построчный JSON. Поэтому:

- закрытие окна гасит демон (и убирает всё за собой);
- если демон упал, GUI напишет «нет связи с демоном», а при следующем запуске демон сам приберёт мусор;
- лог демона: `~/.local/state/wifikit/daemon.log` — его просит присылать при любой непонятной ошибке.

Проверить руками:

```bash
ls -l /run/user/1000/wifikit.sock     # srw------- вы:вы
pgrep -af "wifikit/daemon.py"         # один процесс, от root
```

## 2. Адаптеры

Роли жёстко разделены:

| роль | что делает | требования |
|---|---|---|
| **Сенсор** | скан, захват, деаут | драйвер с monitor-режимом и инъекцией |
| **Фейк-точка** | поднимает AP с порталом | драйвер с AP-режимом (nl80211) |

Один интерфейс нельзя назначить на обе роли — приложение откажется: физически адаптер не сможет
одновременно ловить эфир на канале жертвы и вещать на своём.

Выбор в шапке: «Сенсор» и «Фейк-точка». Если пишет «(непригоден)» — `iw phy` не показал нужный режим,
такой пункт заблокирован. Кнопка «Обновить» перечитывает список (после переподключения адаптера).

Что делать, если адаптер не виден:

```bash
lsusb                        # устройство есть?
iw dev                       # интерфейс создан?
sudo rfkill unblock wifi     # заблокирован?
sudo dmesg | tail -30        # драйвер ругается?
```

Realtek-карты «с Windows-драйвером» иногда монтируются как флешка — их надо переключать
`usb_modeswitch`; в этом случае `lsusb` покажет странный класс устройства.

## 3. Проект

**Проект — это папка на диске, а не состояние в окне.** Создаётся кнопкой «Новый проект» в левом нижнем
углу, имя любое. Появляется `~/wifikit-projects/<имя>-<дата-время>/`:

```
проект/
  project.json        состояние: цель, адаптеры, шаблон портала, найденный пароль, заметки
  dump/*.pcapng       сырые дампы эфира (по одному на попытку захвата)
  hash/*.hc22000      сконвертированные хэши для hashcat
  hash/candidates.txt вендорские кандидаты из hcxpsktool
  ap/hostapd.conf     конфиг поднятой точки и dnsmasq.conf, portal.nft
  report/*.md|html    отчёты
```

Зачем: захват и крошилка работают **только внутри проекта**. Это защита от классического «поймал хэш,
закрыл окно, потерял». Плюс любой проект можно открыть завтра и продолжить с того же места — потифайл
hashcat тоже лежит в проекте, поэтому уже проверенные пароли не проверяются заново.

«Открыть» — выбрать папку проекта (файловый диалог). «Отчёт» — выгрузить Markdown с фактами и паролем.

Что происходит при создании: заводится папка и `project.json` с правами `0600`; цель пока пустая,
адаптеры подтягиваются текущие. Дальше цель появляется сама, как только вы выберете точку в «Точках»
или запустите захват — она записывается в проект.

## 4. Скан

Кнопка «Сканировать» на странице «Точки». Сенсор на время скана переводится в managed (если был в
monitor), снимается с управления NetworkManager, затем опрашивает эфир `iw dev … scan`.

Колонки:

- **SSID** — имя сети (`<скрытая>`, если beacon без SSID);
- **BSSID** — MAC точки; по нему идёт вся дальнейшая работа;
- **Кан** — канал, он же будет зафиксирован при захвате;
- **Сигнал** — RSSI, `-40` рядом, `-85` далеко;
- **Защита** — `WPA2`, `WPA3`, `WPA`, `OPEN`; `PMF!` означает «защита кадров обязательна»;
- **Чем брать** — подсказка по этой конкретной точке (см. §5).

Клик по строке задаёт цель: она уезжает в шапку и на страницы «Захват» и «Злой двойник», а также
в проект как `target`.

## 5. Захват: что именно ловим

Есть два разных материала, и путать их нельзя.

### PMKID (кнопка «Сначала PMKID»)

Многие точки в первом сообщении рукопожатия отдают PMKID — производную от пароля. Его достаточно,
чтобы проверять пароли оффлайн. Клиент в сети не нужен: `hcxdumptool` сам отправляет ассоциацию
и ждёт ответ. Обычно 5–60 секунд.

Плюсы: никого не выкидывает из сети, быстро, работает на пустой сети.
Минус: только там, где точка вообще отдаёт PMKID. Новые прошивки и WPA3 часто не отдают.

### Рукопожатие 4-way (кнопка «Захватить»)

Нужен живой клиент, который подключается к точке. `hcxdumptool` слушает канал; чтобы заставить
клиента переподключиться, включается деаут (`aireplay-ng`) — адаптер шлёт кадры «отключись» от имени
точки. Телефон на секунду выпадает и переподключается — в этот момент ловятся M1/M2/M3.

Галочка «Деаут при захвате» это и включает. Без неё можно ждать пассивно (клиент переподключится сам,
когда захочет) — иногда это единственный путь, если точка игнорирует деаут.

### Почему бывает «хэш не получен»

| Ситуация | Что значит | Что делать |
|---|---|---|
| PMKID 0, EAPOL 0 | точка не отдаёт PMKID, клиентов не было | включить деаут, подключить клиент |
| «есть EAPOL без M2M3» | пара неполная, крошить нельзя | повторить захват, дольше держать |
| «PMF обязателен» на старте деаута | точка игнорирует деаут | PMKID или пассивный захват |
| WPA3-only | SAE-обмен не крошится | только PMKID/переходный режим WPA2/WPA3 |
| не идёт вообще | не тот канал / адаптер не в monitor | диагностика, тест инъекции |

Лимит «мин» — это таймаут `hcxdumptool` (`--tot`). Захват останавливается сам, как только поймана
пригодная пара (`--exitoneapol`), либо по таймауту, либо кнопкой «Остановить захват».

После остановки приложение конвертирует дамп, **отфильтровывает пары по MAC цели** (в хэш не попадут
соседние сети) и считает качество: сколько PMKID, сколько EAPOL, есть ли `M2M3` и проверен ли
`replaycount` (не подделка ли).

## 6. Крошилка

Все атаки — это один и тот же `hashcat -m 22000` по хэшу из проекта; отличаются только тем, откуда
берутся кандидаты. Прогресс, скорость и находки читаются из вывода hashcat.

### 6.1. Словарь

Берётся файл построчно: одна строка — один кандидат. Подходит `rockyou.txt`, любые утечки, свои списки.
Словарь — самый быстрый способ: современная слабая точка ломается за минуты, если пароль в списке.

### 6.2. Правила (к словарю)

Правило — это инструкция «как изменить слово», а не список паролей. Один и тот же словарь с правилами
проверяет десятки модификаций каждого слова: `password` → `Password`, `PASSWORD`, `password1`,
`password!`, `p@ssword`, `drowssap` и т.д. Это ловит человеческую привычку «добавлю цифру в конец».

Пресеты в приложении:

| правило | что делает | когда включать |
|---|---|---|
| **best64** | 64 классические модификации (регистр, цифра в конец, `!`, повтор) | первым делом, почти всегда |
| **dive** | агрессивнее: больше вариантов регистра, l33t, суффиксы | после best64, если не нашлось |
| **rockyou-30000** | 30000 правил, выведенных из утечки rockyou | когда слов мало, а пароль явно «человеческий» |

Своё правило — обычный файл hashcat `.rule`, дайте полный путь (выбор файла сейчас не предусмотрен:
положите правило в `/usr/share/hashcat/rules/` и укажите имя).

Скорость падает пропорционально числу правил: 30000 правил — это ×30000 к перебору. На CPU в виртуалке
это часы, на GPU — минуты.

### 6.3. Маска

Маска — шаблон пароля в синтаксисе hashcat. Символ `?` вводит класс:

| токен | что значит |
|---|---|
| `?d` | цифра 0–9 |
| `?l` | строчная латинская |
| `?u` | ПРОПИСНАЯ латинская |
| `?h` | hex (0–9a–f) |
| `?s` | спецсимволы (`!@#$…`) |
| `?a` | всё печатное ASCII |
| `?b` | любой байт (0x00–0xff) |

Пример: `?u?l?l?l?l?d?d?d` = «Заглавная, четыре строчных, три цифры» — 8 символов. Обычный символ в маске
(не после `?`) — это сам символ: `?d?d-?d?d` = «две цифры, дефис, две цифры».

Поле «Маска» редактируемое: можно выбрать пресет или вписать своё. Свои классы (`-1 abc`) в этом режиме
недоступны — для них есть режим «по позициям».

### 6.4. Словарь + маска (гибрид)

К каждому слову из словаря приписывается хвост по маске: `hashcat -a 6`. Словарь `имя`, маска `?d?d?d`
→ `имя000`, `имя001`, … `имя999`. Это ловит «слово + год» и «слово + пин».

Обратный вариант (маска + слово, `-a 7`) в GUI не выведен: пользуйтесь режимом «по позициям», если
нужна фиксированная приставка.

### 6.5. По позициям — и чем это отличается от маски

**Маска** — это строка в техническом синтаксисе, где вы вручную считаете позиции и не имеете своих
наборов символов (кроме `-1…-4` через командную строку).

**По позициям** — та же маска, но собираемая мышью, с четырьмя вещами, которых в строке нет:

1. **Фиксированный символ в позиции.** Позиция 6 = `-` — значит дефис там обязан быть. В строке это
   тоже можно (`-`), но легко ошибиться с экранированием.
2. **Свой набор на позицию.** Позиция 1 = набор `QWE` — перебирается только Q, W, E. Приложение само
   присваивает набору номер (`?1`) и передаёт `-1 QWE`; до 4 разных наборов.
3. **Диапазон длины.** «от 8 до 12» — hashcat идёт в инкрементальном режиме (`-i --increment-min/max`),
   недостающие позиции добиваются типом последней заданной. Вручную для этого надо писать отдельную
   команду на каждую длину.
4. **Оценка объёма до запуска.** Под таблицей сразу видно маску и число комбинаций — чтобы не запускать
   перебор на 6 квадриллионов «на всякий случай».

Смысл один и тот же: перебрать все комбинации по шаблону. Разница — в способе задать шаблон и в защите
от опечаток.

Пример: пароль `Qwerty-123`.
Позиции: `ПРОПИСНЫЕ`, `строчные` ×4, `символ` `-`, `цифры` ×3, длина 9 → маска `?u?l?l?l?l-?d?d?d`,
объём 26·26⁴·10³ ≈ 11.8 млрд.

### 6.6. Вендорские кандидаты

Кнопка «Вендорские кандидаты» вызывает `hcxpsktool`: он генерирует пароли по шаблонам производителей
из SSID и BSSID (`TP-Link_1A2B` → `tp-link1a2b`, даты, дефолтные `admin123` и т.п.). Результат пишется
в `hash/candidates.txt` и подставляется в поле «Словарь». Это часто быстрее, чем любой брутфорс —
на дешёвых роутерах пароль предсказуем.

### 6.7. Сколько это займёт

Время ≈ объём перебора ÷ скорость. Скорость показывает сама крошилка.

- В виртуалке на Apple Silicon GPU нет: `hashcat` работает на CPU, реально 5–50 тыс. H/s для WPA.
  11 млрд комбинаций на 30 тыс. H/s — это ~4 суток. Считайте заранее.
- На машине с GPU — миллионы H/s, те же 11 млрд за минуты.
- Словарь с правилами почти всегда выгоднее маски: 14 млн слов × best64 ≈ 1 млрд «умных» кандидатов
  против 11 млрд тупого перебора.

Остановка («Стоп») не теряет прогресс: потифайл в проекте, следующий запуск продолжит.
Кнопка «Отчёт» фиксирует найденное.

## 7. Злой двойник

Что происходит по шагам, когда вы нажимаете «Поднять точку»:

1. **Клон.** На AP-адаптере ставится MAC, равный BSSID цели, SSID — имя цели, канал — канал цели.
   Для клиента это «та же сеть».
2. **Точка.** Запускается `hostapd` (открытая сеть, без пароля — иначе клиент не подключится).
3. **Сеть.** Адаптеру назначается `192.168.77.1/24`, поднимается `dnsmasq`: раздаёт адреса,
   на любой DNS-запрос отвечает этим же адресом.
4. **Перехват.** `nftables` перенаправляет весь HTTP (80) с этого интерфейса на портал на 8080.
   Поэтому браузер и captive-детекторы Android/iOS/Windows открывают форму сами.
5. **Портал.** Отдаёт выбранный HTML-шаблон. Любая отправка формы уходит `POST`-ом внутрь приложения,
   где сохраняются **все** поля, а не только пароль.

### Проверка пароля

Если включено «Проверять пароль по хэшу», введённый пароль проверяется `hcxpmktool` по захваченному
ранее хэшу:

- верный → страница «подключено», пароль пишется в проект;
- неверный → «неверный пароль», форма остаётся;
- проверить нечем (нет хэша или нет `hcxpmktool`) → «проверяем…», без вранья в обе стороны.

Это принципиально: портал не показывает «успех» по факту нажатия кнопки. Иначе вы уйдёте с чужим паролем.

### Свои формы

«Загрузить свой HTML/ZIP». Требования:

- в разметке должен быть `<input type="password">` — иначе загрузка отклоняется (перехватывать нечего);
- `action` формы — `{{ACTION}}` (подставляется `/submit`), либо свой JS, который шлёт `fetch`;
- плейсхолдеры: `{{SSID}}`, `{{VENDOR}}`, `{{LANG}}`, `{{TITLE}}`, `{{ACTION}}`, `{{STATIC}}`
  (префикс для картинок и css внутри шаблона);
- без внешних CDN: у клиента интернета нет, страница должна работать офлайн.

Что ждёт сервер от вашего JS: `POST` на `/submit` (urlencoded или JSON) и ответ
`{"verdict":"ok"|"retry"|"pending"}`. Дальше — как решите: `ok` → экран успеха, `retry` → «неверный
пароль», `pending` → «проверяем…».

### Как это выглядит с телефона

В списке сетей появляются две одинаковые по имени; та, что без интернета, — ваша. После подключения
автоматически открывается форма. Всё, что ввели, видно в таблице «Вводы в портале» с вердиктом.

«Погасить» останавливает всё: портал, dnsmasq, hostapd, снимает правила nft и возвращает адаптер.

## 8. Отчёт

Кнопка «Отчёт» в левом нижнем углу: Markdown (и HTML) в `report/`. Внутри: цель (SSID/BSSID/канал/
шифрование/PMF), адаптеры, найденный пароль, попытки портала, заметки, список файлов проекта.
Пароль в файле — поэтому права `0600` и не выкладывайте отчёт в общий доступ.

## 9. Диагностика

Показывает: версии инструментов (и чего не хватает), список адаптеров с драйверами и ролями,
рекомендации по железу, устройства hashcat (`GPU`/`CPU`).

Кнопки:

- «Снять rfkill-блок» — `rfkill unblock wifi`;
- «Устройства hashcat» — `hashcat -I`: видно, на чём вообще будет считаться.

Красное в диакностике = дальше идти нельзя, начните с него.

## 10. Если что-то пошло не так

| Симптом | Что проверить |
|---|---|
| «нет связи с демоном» | `~/.local/state/wifikit/daemon.log`; `ls -l $XDG_RUNTIME_DIR/wifikit.sock` (владелец — вы, `srw-------`); не отменён ли запрос пароля polkit |
| `Exec format error` в логе | старая установка: файл демона без shebang. Переустановите; вручную — `sudo /usr/bin/python3 /usr/lib/wifikit/daemon.py --check` |
| «не хватает зависимостей» | `sudo packaging/install.sh` ещё раз, затем мастер диагностики |
| «PMF обязателен» | точка защищает кадры управления: деаут бесполезен, берите PMKID |
| «нет хэша» | сначала захват; хэш должен лежать в `hash/*.hc22000` непустым |
| «непригоден» у адаптера | `iw phy | grep -A8 "Supported interface modes"` — нет monitor или AP |
| после аварии висит точка | перезапустите приложение: демон сам снимет nft-правила и вернёт адаптеры |
| GUI не открывается, `xcb` | не хватает `libxcb-*`: `sudo packaging/install.sh` (он их ставит) |

Ответ на любой баг: номер тест-кейса из `docs/TESTCASES.md`, текст «Журнала» и лог демона.
