# Платформы: почему только Linux

| ОС | Скан | Захват 4-way | PMKID | Деаут | Злой двойник | Брутфорс |
|---|---|---|---|---|---|---|
| Linux | да | да | да | да | да | да |
| Windows 11 | да | только Npcap + WlanHelper и «правильный» чип | частично | ограниченно | Mobile Hotspot: без клона BSSID/канала | да |
| macOS | да | только tcpdump на текущем канале | нет | нет | нет | да |

## macOS

`IO80211Family`/CoreWLAN не отдают monitor mode и инъекцию **ни одному** стороннему адаптеру, а
Realtek/MediaTek-драйверы к тому же x86_64-only и на Apple Silicon не грузятся. Промежуточных путей нет:
всё, что показывает Wireshark на `en0`, — пассивный снимок текущего канала без возможности деаута.

Рабочий обход — Linux-гость. На Apple Silicon (M1–M4): UTM, режим **QEMU** (не Apple Virtualization),
в настройках VM включить «USB-устройства → делиться с хостом», контроллер xHCI 3.0, затем пробросить
адаптер в гостя. Без мастер-переключателя галочка в меню USB отрабатывает вхолостую — известная ловушка.

Внутри VM захват и инъекция работают полноценно; крошилка упирается в CPU, потому что GPU не прокинуть.

## Windows

- Monitor mode включается только через Npcap + `WlanHelper.exe <iface> mode monitor`, и только на
  адаптерах, чей нативный драйвер это умеет (MT7921AU, RTL8812AU с оговорками).
- Инъекция зависит от драйвера и часто молча не работает — проверять `aireplay-ng --test`.
- AP-режим: `netsh wlan set hostednetwork` на Win11 полумёртв, «Мобильный хот-спот» не клонирует
  BSSID и канал, а берёт их от подключённой сети. Злой двойник в лучшем случае «похожий».
- WSL2 Wi-Fi-адаптер не видит вообще: там нет `nl80211`.
